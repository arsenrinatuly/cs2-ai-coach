# ADR-002 — Store match evidence in PostgreSQL

Match IDs are SHA-256 digests of recording bytes. An upload of the same bytes
identifies the same match. A Steam ID identifies a player across matches.
A participant stores the name recorded for that match. IDs stay as decimal
strings so unsigned Steam IDs survive database and JavaScript round trips.

Round numbers and event ordinals are scoped to a match. An event ordinal
distinguishes events on the same tick. Death events retain their source tick
and the resolved Steam IDs and sides that Awpy provides. Unresolved
participants are nullable. Round membership can be calculated from the
recorded boundaries, including cases where an event falls outside a round.

Explicit relational constraints preserve identity and allow match-level
deletion of its evidence. Full demo bytes remain outside the database.
The initial migration covers the recorded header, round boundaries, and
death evidence. Additional datasets can be added as evidence requirements grow.
